# 習慣トラッカーアプリ開発ドキュメント（TDD・AI開発用）

## プロジェクト概要

### プロジェクト名
- 習慣トラッカーアプリ（MVP）

### 目的
- React・TypeScript・TDD の実践学習を兼ねた、簡易的な習慣管理アプリケーションを開発する
- プロトタイピングと拡張を意識しつつ、UIと状態管理の設計・最適化（再レンダリング抑制等）を行う

---

## 使用技術・制約

| 項目         | 内容                                         |
|--------------|----------------------------------------------|
| フレームワーク | React + TypeScript + Vite                   |
| 状態管理     | useReducer 中心（Reduxなどは使わない）        |
| テスト       | Vitest（ユニット・コンポーネント）、Playwright（E2E） |
| 永続化       | localStorage                                 |
| TDD方針      | テスト→実装の順で進めること                  |
| UI設計       | Figmaは使用しない。Mermaidによる構造表現を参考とする |
| 言語         | コメントや表示文言は **日本語** に統一すること |

---

## データ構造（型定義）

### `types/habit.ts`

```ts
export type HabitType = 'count' | 'check'
export type FrequencyUnit = 'daily' | 'weekly' | 'monthly'

export type HabitGoal = {
  amount: number // 目標数値（例：3回, 15分）
  unit: 'times' | 'minutes' // 回数 or 分数
}

export type Habit = {
  id: string // 識別子
  name: string // 習慣名（例：水を飲む）
  type: HabitType // 'count' or 'check'
  goal: HabitGoal // 目標設定
  frequency: FrequencyUnit // 毎日・毎週・毎月など
  startDate: string // 習慣を開始する日（YYYY-MM-DD）
  value: number | boolean // 実績値（typeによって型が変わる）
  skipped?: boolean // スキップしたかどうか
}
```

## テストロードマップ（TDD）

### フェーズ0：初期準備

- `types/habit.ts` の定義
- vitest のセットアップ
- `habitReducer.test.ts` 作成

### フェーズ1：reducer テスト（ユニット）

**ゴール：状態のロジックが正しく動く**

| アクション   | 概要                                 |
|--------------|--------------------------------------|
| ADD          | 習慣を新規追加                       |
| DELETE       | 習慣を削除                           |
| INCREMENT    | カウント型の習慣の実績を+1           |
| TOGGLE       | チェック型の習慣の完了状態をトグル    |
| SKIP         | 習慣をスキップ扱いにする             |
| UPDATE       | 習慣内容の編集（名前・目標など）      |

- テストは TDD で進行し、まず `habitReducer.test.ts` を書いてから実装すること

### フェーズ2：コンポーネントテスト

**対象コンポーネント：**
- `HabitItem.tsx`
- `AddHabitForm.tsx`

**テスト観点：**
- UI表示確認（名前・回数などの表示が正しいか）
- 操作イベント（ボタン操作が正しくコールバックするか）
- 表示切替（type に応じて UI が分岐しているか）

### フェーズ3：E2E テスト（Playwright）

**シナリオ：**
- 習慣を追加 → 表示（入力フォーム → 登録後に画面表示されるか）
- 習慣完了 or カウント（値が変化するか（＋/✓））
- 習慣削除（表示が消えるか）
- スキップ（ステータスが変化するか）
- 永続化（リロード後も習慣が保持されているか）
